# v3.10 — Workload Dependency Graph

**Date:** 2026-11-25  
**Branch:** `feat/thm-cpu-pressure-engine`  
**Scope:** cross-root dependency inference and graph-guarded reclaim. No CPU or
memory enforcement algorithm changed; the CPU plane remains scheduling-only.

## What shipped

- `workload/dependency_graph.hpp/.cpp`
  - nodes: workload roots, state, Hyprland class/title evidence;
  - edges: `ProcessAncestry`, `Toolchain` (LSP/build → window-bound root),
    `SharedProject` (same CWD → window-bound root);
  - direction: `from` depends on `to`;
  - `has_active_dependent()` walks dependents transitively.
- Reclaim step 3 and step 7 now consult the graph via an optional pointer.
  The old `other.root_pid == our_pid` check remains as a fallback for callers
  that have not built a graph.
- Daemon now uses a two-pass tick: state/context/CPU first, graph rebuild,
  then policy/enforcement. A successfully reclaimed workload is marked
  terminated in the graph so it cannot shield later candidates in the same
  tick.
- Telemetry emits a `dependency` object; each workload carries
  `dependency_providers`, `dependency_dependents`, and
  `protected_by_dependents`. `titan-hwm status` prints the graph summary;
  `titan-hwm workloads` shows `dep[providers/dependents!]`.

## Honest limits

- The graph models ancestry, LSP/build toolchain, shared CWD, and Hyprland
  window-bound roots. It does not yet model browser tab groups, waits-on, or
  reclassification history.
- No full QEMU/KVM compile A/B was run after v3.10; no median-compile
  improvement is claimed.
- No GPU stress or I/O plane was added.
- Destructive memory reclaim remains off unless
  `THM_ALLOW_DESTRUCTIVE_RECLAIM=1`.

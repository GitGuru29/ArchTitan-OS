# v3.3-R5 — Shared pidfd signal path (2026-11-20)

## What changed

- Added `core/signal_utils.hpp` as the single pidfd-backed signal delivery path:
  - `thm::signal_process(pid, sig)` returns `Signaled` / `Gone` / `Failed`.
  - `thm::process_alive(pid)` for liveness probes.
  - Uses `pidfd_open` + `pidfd_send_signal` syscalls directly, with a guarded
    `kill()` fallback on pre-5.3 kernels.
- Refactored all process-state signal paths to use it:
  - `EnforcementPlane::signal_tree()` (SIGSTOP / SIGCONT)
  - `EnforcementPlane::sigcont_if_stopped()` (thaw)
  - `ReclaimEngine::kill_tree()` (SIGTERM / SIGKILL)
  - daemon startup thaw sweep (SIGCONT)
- Removed the duplicated local `signal_pid()` from `reclaim_engine.cpp`.
- Removed the racy `fs::exists("/proc/<pid>")` check from `signal_tree()`;
  pidfd delivery now makes check-and-signal atomic with respect to PID reuse.
- Telemetry version fixed: default `TelemetrySnapshot::version` is now
  `3.3.0` (was `3.2.0`), and the telemetry contract test checks the new memory
  orchestration fields (`bg_memory_high_bytes`, `latency_memory_high_bytes`,
  `protected_memory_low_bytes`, `memory_enforcement`, `enforcement_degraded`,
  `destructive_reclaim_enabled`).
- Added TC-42 for the shared helper; TC-23 is now the v3.3 telemetry contract.

## Why this matters

The review listed inconsistent pidfd usage as a safety gap. A raw
`kill(pid, sig)` after a separate liveness check has a time-of-check/time-of-use
window: the process can exit and the PID be recycled before the signal lands.
Centralising pidfd delivery means every THM signal path now pins the process
object, not just the number, and reports `Gone` cleanly for reaped PIDs.

The protected-PID and browser-collateral guards remain in the callers; this
change only replaces the delivery primitive.

## Invariants preserved

- HC-CPU-1: no CPU-pressure kill/stop/freeze.
- Protected processes still cannot be signalled by enforcement or reclaim.
- Browser roots still skip SIGSTOP on FREEZE.
- Destructive reclaim still requires `THM_ALLOW_DESTRUCTIVE_RECLAIM=1`.
- Hyprland IPC context path unchanged.

## Reliability phase status

v3.3-R1 through R5 are complete: pressure-relief downgrade, real
`memory.high`/`memory.low`, fail-closed gate, real memory-pressure benchmark,
and unified pidfd signalling. The CPU and memory planes are now reliable enough
to build the v3.4 workload-intelligence layer on top of the existing Hyprland
IPC context stream.

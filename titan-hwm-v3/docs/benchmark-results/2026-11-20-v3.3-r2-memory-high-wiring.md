# v3.3-R2 — Kernel-native memory.high / memory.low wiring (2026-11-20)

## What changed

- `THROTTLE` now performs a real kernel-native soft limit instead of only
  raising `oom_score_adj`:
  - `compute_memory_high_bytes()` sets `memory.high` to **75% of the summed RSS**
    of throttled workloads, with a 16 MiB floor so tiny jobs do not get an
    unusably small limit.
  - Background and latency slices are limited independently.
- `memory.low` is now applied to `archtitan-active.slice` and
  `archtitan-protected.slice`, protecting the full active/protected RSS but
  never more than **half of total RAM**.
- All memory control writes are change-detected; steady state costs zero
  cgroup syscalls.
- `CgroupController::set_memory_low()` added as a best-effort write (kernels
  without `memory.low` support are a no-op).
- Telemetry fixes:
  - `latency_cpu_weight` is now assigned from the live CPU policy (it used to
    publish a stale `450`).
  - New fields: `bg_memory_high_bytes`, `latency_memory_high_bytes`,
    `protected_memory_low_bytes`, `memory_enforcement`.
- TC-40 validates the pure memory math.

## Why this matters

The review finding was that `set_memory_high()` existed but had no caller, so
`THROTTLE` was effectively only OOM exposure plus a CPU weight cap. This task
closes that gap: THM now asks the kernel to reclaim from throttled slices first
via `memory.high`, and protects foreground/protected slices via `memory.low`.
No signal is sent by this path.

Hyprland IPC remains the primary context provider: focus/visibility events
still drive the workload state machine and policy before RSS is aggregated.

No CPU regression from the memory wiring. The cgroup-headroom and zero-kill
checks remain authoritative.

## Invariants preserved

- HC-CPU-1: no CPU-pressure kill/stop/freeze.
- No destructive reclaim introduced by this task.
- Latency slice still never receives `cpu.max` or `cpu.idle`.
- Observed workloads still bypass the memory policy plane.

## Caveats / next task

This validation does **not** yet include a real RAM-exhaustion run. The next
task will add a fail-closed cgroup mode, a default-off destructive reclaim
gate, and a real memory-pressure benchmark that verifies actual
`memory.high`/`memory.low` values and freeze/thaw behavior.

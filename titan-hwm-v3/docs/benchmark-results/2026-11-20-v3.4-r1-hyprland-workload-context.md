# v3.4-R1 — Hyprland workload-context layer (2026-11-20)

## What changed

- Formalised the existing Hyprland IPC stream as the workload-context provider:
  - `WorkspaceState` now carries `last_focused`, stamped by
    `WorkspaceMonitor` on every Hyprland `workspace` event.
  - Added `WorkspaceState::context_active()` with a bounded 30-second
    recent-focus window (`kRecentFocusWindowS`).
  - Added `seconds_since()` to `core/types.hpp`.
- Replaced every raw `(ws.is_focused || ws.is_visible)` check with
  `ws.context_active()` across:
  - `WorkloadManager::tick()` (state machine)
  - `PolicyEngine::evaluate()` (policy tier)
  - `EnforcementPlane::observed_slice_assignment()` (slice routing)
- Added TC-43 to prove the context window helps then expires cleanly.

## Why this matters

This is the first v3.4 workload-intelligence piece and it is built directly on
the Hyprland IPC events THM v3 already listens to. A fast workspace switch no
longer causes an immediate downgrade: for 30 seconds the recently-left
workspace still counts as foreground context, so its workloads stay `ACTIVE`
and receive `KEEP_FULL`. After the window expires the normal aging path runs,
so the protection is bounded and cannot pin resources permanently.

Default-constructed `WorkspaceState` values have no `last_focused` stamp, so all
existing callers and tests retain exactly the previous behavior.

### Synthetic CPU headroom A/B

```text
./build/bench_cpu_headroom --compare --profile mixed \
  --duration 8 --threads 16 --bg-procs 2 --adaptive both --no-color
VERIFICATION SCORECARD: 8/8 PASSED  (after one noisy 7/8 rerun)
HC-CPU-1 Worker Survival: 2/2 baseline, 2/2 managed (0 killed/stopped)
```

The first run failed only `mixed:THROUGHPUT_PRESERVED`; an immediate rerun was
8/8. As documented before, throughput jitter on this shared host is noisy, so
the authoritative checks remain the cgroup counters and the invariant suite.

## Invariants preserved

- HC-CPU-1: no CPU-pressure kill/stop/freeze.
- Hyprland IPC remains the primary context provider; no parallel context source
  was introduced.
- Recent-focus protection is bounded at 30 seconds, never permanent.
- Destructive reclaim still requires explicit opt-in.
- Observed workloads still bypass enforcement.

## Next direction

Continue the v3.4 dependency/workload graph: promote Hyprland window-class and
process-ancestry signals into a first-class context record, then evaluate
coordination policies (e.g. build + IDE + game together) without adding new
I/O or GPU control planes.

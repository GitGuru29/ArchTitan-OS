# v3.3-R4 — Real cgroup memory-pressure benchmark (2026-11-20)

## What changed

- Added `benchmarks/bench_memory_pressure.sh`, a real cgroup v2 memory-pressure
  harness.
- It starts a transient systemd user scope with:
  - `MemoryHigh=96M`
  - `MemoryLow=32M`
  - `MemoryMax=192M`
  - allocator target: 128 MiB in 8 MiB touched chunks
- It discovers the real cgroup path from `/proc/self/cgroup` inside the scope
  (systemd places it under `app.slice`), samples `memory.current`,
  `memory.high`, `memory.low`, and `memory.events` every 200 ms, and verifies:
  - observed limits match requested limits
  - `memory.events.high` increments (kernel reclaim pressure was real)
  - `oom_kill == 0`
- It deliberately operates in a transient test scope, never in THM's own
  `archtitan.slice`, so it cannot disturb the daemon or user workloads.

## Why this matters

This is the first real RAM-pressure test in the tree. The earlier memory work
was unit-tested only. This run proves the exact kernel primitives THM now uses
(`memory.high`, `memory.low`, `memory.events`) behave as expected on this host
under bounded pressure.

## Results

```text
unit = archtitan-mem-bench-73838.scope
cgroup = .../user@1000.service/app.slice/archtitan-mem-bench-73838.scope

Requested memory.high: 100663296 bytes
Observed memory.high:  100663296 bytes
Requested memory.low:  33554432 bytes
Observed memory.low:   33554432 bytes
Peak memory.current:   96899072 bytes
memory.events high:    18
memory.events max:     0
memory.events oom:     0
memory.events oom_kill: 0

RESULT: PASS
```

Unit suite remained green:

```text
./build/thm_test_runner
TOTAL: 41/41 PASSED (100% SUCCESS)
```

## Interpretation

- The kernel accepted and enforced the exact soft/hard limits requested.
- 18 `high` events show that reclaim pressure occurred repeatedly while the
  allocator held memory, not merely that the files were written.
- No `max`, `oom`, or `oom_kill` events occurred: the allocator stayed inside
  its safe envelope and no process was terminated.
- `systemd-oomd` was not observed to intervene. A full coexistence audit with
  `systemd-oomd` and the kernel OOM killer is still a separate reliability item.

## Invariants preserved

- HC-CPU-1: no CPU-pressure kill/stop/freeze.
- Destructive reclaim remains disabled by default (`THM_ALLOW_DESTRUCTIVE_RECLAIM`
  opt-in).
- THM's own cgroup slices were not touched.
- Hyprland IPC context path unchanged.

# v3.3-R3 — Fail-closed enforcement gate (2026-11-20)

## What changed

- Added `sanitize_decision()` as the single fail-closed gate before enforcement
  in the daemon tick:
  - unwritable cgroup hierarchy → `FREEZE` and `RECLAIM` downgraded to
    `KEEP_BACKGROUND` (no raw fallback signals)
  - `RECLAIM` downgraded to `FREEZE` unless `THM_ALLOW_DESTRUCTIVE_RECLAIM=1`
- Destructive reclaim is now **off by default**. The explicit opt-in must be
  set in the environment; telemetry publishes `destructive_reclaim_enabled`.
- Cgroup health is sampled once per tick and telemetry publishes
  `enforcement_degraded`.
- Memory-soft-limit writes now reuse the same cgroup-health authority.
- TC-41 validates every downgrade branch and confirms `THROTTLE`/`KEEP_FULL`
  are preserved.

## Why this matters

Earlier, a cgroup setup failure only printed a warning, after which signal
paths could still run. That meant THM could degrade from "orchestrator using
kernel primitives" to "script sending SIGSTOP" without telling anyone. The
fail-closed gate removes that silent downgrade: if the kernel mechanisms THM
is designed around are unavailable, THM stops taking destructive actions and
reports the condition.

Hyprland IPC focus/visibility decisions are unaffected: they remain the primary
context provider and still drive `KEEP_FULL` / `KEEP_BACKGROUND`.

## Invariants preserved

- HC-CPU-1: no CPU-pressure kill/stop/freeze.
- No destructive reclaim without explicit opt-in.
- No signal fallback when cgroups are unavailable.
- Hyprland IPC context path unchanged.

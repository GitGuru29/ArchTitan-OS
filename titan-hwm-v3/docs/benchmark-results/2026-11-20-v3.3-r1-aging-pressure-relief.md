# v3.3-R1 — AGING pressure-relief downgrade (2026-11-20)

## What changed

- `WorkloadManager::tick()` now returns an `AGING` workload to `IDLE` when
  memory pressure falls below `MODERATE`. Previously `AGING` was a one-way
  degradation: a short pressure spike could leave an old workload permanently
  `THROTTLE`d after the machine had recovered.
- Hyprland IPC focus/visibility and measured execution are still checked first,
  so live user context continues to win over pressure. This keeps the existing
  workspace-event-driven model as the primary context provider.
- Added TC-39 to prove the downgrade, re-qualification, and focus rescue.

## Why this matters

The memory state machine now has symmetric entry/exit for pressure-driven
degradation:

```text
IDLE --(age >= 5 min && pressure >= MODERATE)--> AGING
AGING --(pressure < MODERATE)------------------> IDLE
```

A later pressure spike must re-qualify the workload through the state machine
before it can be throttled again.

`mixed_BASE:FG_PROBE_ALIVE` and `mixed:DEADLINE_MISSES_REDUCED`; an immediate
rerun was clean at 8/8. This is consistent with the benchmark record's existing
note that jitter metrics on this shared host are noisy. Authoritative checks
remain the cgroup counters, reservation math, and invariant tests.

## Invariants preserved

- HC-CPU-1: no CPU-pressure kill/stop/freeze.
- Hyprland IPC focus/visibility still upgrades and rescues workloads.
- Observed workloads still never enter `AGING`/`RECLAIMABLE`.
- No enforcement behavior changed for `RECLAIMABLE` workloads.

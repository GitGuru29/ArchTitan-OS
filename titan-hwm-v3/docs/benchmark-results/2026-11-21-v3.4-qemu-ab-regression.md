# v3.4 QEMU/KVM A/B — regression fixed, daemon RSS cut below 6 MB

Original failing commit: `cbefd6ba12079f92c81ff3ee880a37447f38b0e5`
Fix baseline: v3.4-R2 (`3980adc`)
Throughput fix: v3.4-R3 (`e64e261`)
Daemon-cost fix: v3.4-R4 (`47e3399`)
Pressure-aware tick: v3.4-R5 (`69143c0`)
RSS fix: v3.4-R6 (this change)

## Original result (FAIL)

THM v3.4 completed **1** compile round in **468259 ms** versus **5** rounds at
**47567 ms** median with THM disabled — a **9.8x** slowdown. Swap-out was
401085 pages vs 0. The last action in arm A was `THROTTLE (g++)`.

## Root causes found

1. **Slice-wide `memory.high`** on `archtitan-background.slice`, which also held
   executing builds.
2. **Headless presence assumption.** With no Hyprland IPC, THM kept a 50%
   `cpu.max` cap on background work.
3. **Compiler children frozen.** Short-lived `cc1plus` children looked
   IDLE/AGING and received `FREEZE` under HIGH memory pressure.
4. **Fixed per-tick overhead.** The daemon's scan/telemetry loop and low
   child/parent cgroup weights reduced CPU available to the compiler.

## Fixes

### v3.4-R2 / R3 / R4 / R5

- R2: `archtitan-throttled.slice`, headless cap lift, bulk freeze guard.
- R3: headless bulk child weight `1000`, parent `archtitan.slice` weight `2000`,
  full `/proc` metadata every 5 s. Regression 9.8x → 1.17x, median 38.6 s.
- R4: no `hyprctl` forks on headless hosts; governor sysfs scan on change/5 s;
  telemetry at 1 Hz in headless bulk; 400 ms calm headless tick.
- R5: pressure-aware tick — 400 ms while memory is `NORMAL` and CPU is not
  `CRITICAL`, snapping to 200 ms otherwise. Clean run: median 20.3 s, daemon
  10.64%, min MemAvailable 658 MB, 0.5 s stalls.

### v3.4-R6 — daemon RSS under 6 MB

Two deterministic RSS reductions:

1. **One glibc malloc arena.** The daemon's short-lived threads no longer get
   separate arenas (`MALLOC_ARENA_MAX=1` + `mallopt(M_ARENA_MAX, 1)` at startup).
2. **Static C++ runtime.** The daemon links `-static-libstdc++ -static-libgcc`,
   so it maps only the used C++ code instead of ~1.4 MB of `libstdc++` text and
   rodata. `ldd` now shows only libc/libm/loader.

Local dry-run peak RSS fell **5.7 MB → 4.8 MB**. In the final QEMU arm the
sampled peak was **4.2 MB** (summary rounds it to 4 MB), comfortably below the
6 MB budget.

### Rejected experiments

- **Unconditional 1 Hz tick:** lost hog containment (one 337 s round).
- **Unconditional 400 ms tick:** cut CPU but dropped min MemAvailable to 37 MB.
- **500 ms calm tick + 10 s metadata + 5 s telemetry:** pushed compile back to
  65–72 s; reverted.
- **Periodic `malloc_trim(0)`:** caused multi-second pauses (collector tick max
  3.4 s); removed. The one-arena + static-runtime change alone delivers the RSS
  win without stalls.

### Honest caveats

- The host was in a slow/contended state during all R6 runs: THM-off itself was
  48–54 s, versus 19 s in the clean R5 run. Absolute R6 compile times therefore
  are **not comparable** to R5. The robust result versus THM-off in the same
  back-to-back run is **1.15x**, down from the original 9.84x.
- Daemon CPU likewise inflated with host load: R6 final A was 17.76%, while the
  clean R5 run was 10.64%. The deterministic savings are still the removed
  `hyprctl` forks, cpufreq scan, and per-tick JSON.
- RSS is the reliable win: **4.2 MB** sampled peak, verified locally as 4.8 MB
  dry-run, with no `malloc_trim` pauses.
